## 1. 业务背景与产品定位

在个人与家庭财务及人情管理场景中，用户常面临三大痛点：
1. **人情重要事件遗忘**：亲友婚礼、满月、乔迁等礼尚往来事件（`gift_event_info_t`）缺乏提前一天与当天的集中提醒；
2. **消费券过期作废**：已领取但未核销完毕的消费券（`cpn_coupon_info_t`）过期才被发现；
3. **猫超卡与预付卡余额沉睡过期**：天猫超市享淘卡/账户记录（`account_record_info`）与商超预付消费卡（`prepaid_card_info_t`）临期缺乏醒目预警；
4. **消息打扰与渠道个性化诉求**：不同用户对提醒渠道敏感度不同。部分用户希望接收微信服务号模板消息但关闭站内信，部分用户希望只保留重要喜事通知而静音营销券类推送。

为此，系统构建统一的 **「系统消息与多业务到期提醒中心」**，打通移动端底部「消息」Tab、PC 端顶部铃铛通知抽屉、微信公众号模板消息推送与**用户个性化推送渠道开关配置**，采用 **100% XXL-Job 后台定时任务全量巡检（`sysMessageRemindHandler`）+ 唯一幂等键（`dedup_key`）落库 + 8大业务分类渠道个性化拦截 + 微信模板消息联动推送 + 业务页面一键直达** 架构。

### 2.2 移动端交互体验 (`alex_miaosha_mobile`)
- **底部 TabBar 未读角标**：首页与消息页加载时自动同步未读总数，展示在底部导航栏「消息」图标右上角（超过 99 显示 `99+`，0 条时自动隐藏）。
- **分类胶囊与快捷筛选**：支持 `[全部 / 礼金事件 / 消费券 / 猫超/预付卡 / 系统通知]` 横向胶囊切换（附各类别未读数微标）、关键词搜索及「仅未读」一键过滤。
- **左滑手势与业务直达**：卡片支持左滑「标为已读 / 删除」，点击卡片自动消除未读红点并跳转至对应业务管理页面。
- **新增自定义提醒**：右上角「新增提醒」支持随时录入个人备忘或系统通知（已移除手动巡检按钮，提醒由后台 XXL-Job 100% 自动生成）。

- **通知中心抽屉 (`MessageCenterDrawer.vue`)**：点击铃铛滑出 460px 宽通知抽屉，支持分类 Tab 切换、「全部已读」、「新增提醒」及单条「去处理」路由直达。
- **通知偏好设置入口**：右上角提供「⚙️ 通知设置」按钮，一键唤出 560px 独立偏好配置抽屉。

## 3. 用户个性化推送渠道偏好配置 (User Notice Channel Config)

为满足不同用户的精细化推送偏好，系统设计了**8 大业务分类 × 双渠道（站内信 + 微信推送）的个性化独立控制矩阵**：

### 3.1 业务大类划分与映射字典 (`NoticeBizType`)
1. **`GLOBAL`（全局总控）**：具备一票否决权，关闭后下级所有业务渠道强制静音；
2. **`GIFT_EVENT`（礼金大喜事提醒）**：喜事当天/前1天倒计时提醒；
3. **`GIFT_RETURN`（人情回礼预警）**：亲友有喜事待还礼、礼金严重失衡提醒；
4. **`COUPON`（消费券到期提醒）**：消费券临期与当天到期提醒；
5. **`PREPAID_CARD`（预付卡/猫超卡到期）**：猫超卡与预付消费卡临期提醒；
6. **`BUDGET_OVER`（月度预算超支预警）**：开销达到或超过设定限额的风险预警；
7. **`FINANCE_REPORT`（财务汇总分析推送）**：周期性收支分析简报推送；
8. **`SYSTEM`（基础系统公告与安全提醒）**：系统升级维护、安全登录等通知。

### 3.2 渠道正交性与两级决策规则
- **双渠道正交独立**：系统内部站内信（是否持久化并在页面显示）与微信推送（是否调用微信模板消息接口）互不干扰。关闭站内信不会影响微信推送，关闭微信也不会阻碍站内信生成；
- **两级决策与一票否决权**：
  - 若用户配置了 `GLOBAL` 站内信关闭，则所有 7 个子项业务的站内信均被一票否决；
  - 若用户配置了 `GLOBAL` 微信关闭，则所有 7 个子项业务的微信推送均被一票否决；
  - 只有在 `GLOBAL` 开启时，才由具体子业务开关接管判定；
- **零数据膨胀默认放行（Ponytail 极简原则）**：
  - 新用户注册时，数据库不预插任何记录；服务层与前端默认恒定放行（站内信=开启，微信=开启）；
  - 仅当用户在前端主动切换开关时，才向 `user_notice_config_t` 执行单条 Upsert 写入。

### 3.3 前端交互与视觉范式 (`UserNoticeConfigDrawer.vue`)
- **100% Tailwind CSS 原子类构建**：遵循 Taste-Skills 与 Impeccable 美学，适配深色模式（Dark mode）；
- **全局总控卡片**：顶部渐变卡片突出「一票否决」标识，集成站内信总控与微信总控双开关；
- **业务条目双行卡片**：7 大业务卡片分列，下级开关在总控关闭时自动呈现「禁用置灰」与 Tooltip 说明（如：“全局微信推送总控已关闭，一票否决生效中”）；
- **极速乐观更新**：开关切换本地即刻响应，后台异步持久化，网络异常时平滑回滚并给出友好 Toast。

## 4. 验收标准 (Acceptance Criteria)

- **[AC1] 提醒准确性与微信联动**：当天/次日举行的礼尚往来事件、剩余 `0~3` 天且未核销完的消费券、剩余 `0~3` 天且余额大于 0 的猫超卡与预付卡均能由 XXL-Job 准确生成对应阶段站内信，并自动触发微信公众号模板消息推送。
- **[AC2] 严格幂等与防复活**：同一业务记录在同一提醒阶段同一天仅生成一条消息、仅推送一次微信模板消息；用户标为已读或主动删除后，再次巡检绝不重复生成。
- **[AC3] 权限隔离与异常降级**：用户仅可查看、标为已读或删除归属本人或本机构的提醒消息，跨用户操作返回 `403` 拒绝；微信推送失败不影响站内信正常落库。
- **[AC4] 个性化推送渠道开关精准拦截**：
  - 当用户在某业务（如 `COUPON`）关闭微信通知后，该用户对应业务的微信模板消息调用次数为 0，站内信正常落库；
  - 当用户关闭某业务站内信后，巡检跳过站内信插入（入库增加数为 0），微信通道正交放行；
  - 当用户关闭 `GLOBAL` 总控时，对应渠道全部业务强制静音（一票否决生效）。
