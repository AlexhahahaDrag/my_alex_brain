## 2. 后端四大强制工程红线 (Ponytail Red Lines)

> [!CAUTION]
> ### ⛔ 严禁违背的四大后端红线
> 1. **ID 序列化安全（防 JS 精度截断）**：
>    - 后端所有 DTO/VO 的 `Long` 主键/外键字段，**统一标注序列化注解**：
>      ```java
>      @JsonSerialize(using = Long2StringSerializer.class)
>      private Long id;
>      ```
> 2. **数据权限动态注入防越权 (`@DataPermission`)**：
>    - 数据权限仅在调用标注了 `@DataPermission` 的**自定义 Mapper 方法**时生效；
>    - **严禁直接调用 MyBatis-Plus `IService` 默认的 `page(Page, Wrapper)`、`list()`、`updateById()`**，否则拦截器会被彻底绕过导致跨租户/跨机构数据越权！
> 3. **异步并行登录必须显式 `join()`**：
>    - 在登录逻辑中，异步获取头像与权限树上下文后，**必须通过 `CompletableFuture.allOf(...).join()` 显式同步等待**，再写入 Redis 并响应前端，严禁漏等导致前端 401/403 异常。
> 4. **单用户单有效机构事务保障**：
>    - 变更机构绑定时，必须在一个严密事务内将原记录置为 `status=0`，并插入新有效关系 `status=1`。
> 5. **AI 智能服务调用必须配置降级熔断与领域启发式保活 (`fallbackFactory`)**：
>    - 跨微服务调用 `alex_miaosha_ai` 时，必须使用 `AiAnalyzeApi` 及其 `AiAnalyzeFallbackFactory`，严禁在业务线程中同步无超时阻塞等待，确保在未注入 `AI_DEEPSEEK_API_KEY` 或外部大模型网络超时（15s）时平滑降级；
>    - 各业务域（如 `CouponAiService`, `ProductAiService`, `RoleAiService`, `GiftAiService`）必须内置确定性的启发式规则（Heuristic Rules）兜底，在 Feign 熔断或降级时输出符合业务常识的有效方案（如按品类/预算推导券规则、按商品亮点生成卖点、按岗位名称推导权限节点），确保核心业务体验连续不中断。
> 6. **公共契约与运行时分层红线 (`common_api` vs `common_core`)**：
>    - 任何 RPC 接口契约模块（`*_api`）**严禁直接引入包含 Web 运行时的 `common_core`**，必须且仅能依赖轻量纯契约包 `common_api`；
>    - 网关层（`alex_miaosha_gateway`）严禁引入任何 Servlet Web / Undertow / Tomcat 依赖，坚决杜绝 WebFlux 响应式网关发生类路径冲突。
> 7. **对象存储流式安全与 S3 存取红线 (`BaseS3Template`)**：
>    - **流生命周期规约**：存储工具层（`fileDownload`）严禁在 `finally` 块中过早 `close()` 输入流；流的关闭必须且仅能由最终使用/消费端负责；
>    - **严禁误用 `available()`**：上传文件时必须通过 `file.getSize()` 传入真实字节长度，严禁依赖 `available()` 导致大文件在分片传输中被截断；
>    - **消除写操作网络 RTT**：统一基于 `BaseS3Template` 的内存 Bucket 缓存机制，禁止每次上传重复网络探测 Bucket 是否存在；
>    - **内外网签名隔离**：支持配置 `publicUrl` 替换预签名 URL 中的物理 Host，禁止将底层存储内部 IP 与内部端口直接外泄。
> 8. **公共基础设施包命名与组件分层规约 (`common_core` 包结构规范)**：
>    - **根包统一约束**：`alex_miaosha_common` 旗下所有组件与类必须严格归属于统一命名空间根包 `com.alex.common`，**坚决杜绝在根路径逃逸衍生孤儿包（如 `com.alex.utils`）**，各微服务统一仅需扫描 `com.alex.common`；
>    - **组件按职责正交归类**：AOP 切面类统一放置在 `com.alex.common.aspect`；纯工具类统一归入 `com.alex.common.utils.<domain>`（例如 `com.alex.common.utils.ip.IpUtils`）；
>    - **严禁领域模型下沉与死代码残留**：基础底座严禁依赖具体上层业务领域对象（如秒杀 DTO转换类），严禁残留空骨架/全注释拦截器，杜绝下游微服务为了规避报错而配置奇形怪状的 `@ComponentScan.Filter` 排除过滤器。
> 9. **Windows 控制台日志编码规约 (`logback-spring.xml` STDOUT)**：
>    - **控制台终端对齐**：Windows 操作系统终端默认运行在 Code Page 936 (GBK) 环境下，各微服务 `logback-spring.xml` 中的控制台 `STDOUT` Appender 的 `<charset>` 统一指定为 `GBK`，避免 Spring Boot 自动注入的 `console.encoding=UTF-8` 导致 Windows 终端按 GBK 查表渲染出 `同氮胺聚信...`（UTF-8 字符流被 GBK 查表解释）的典型乱码；
>    - **磁盘文件保持 UTF-8**：所有落盘文件 Appender（`RollingFileAppender`）必须硬编码维持 `<charset>UTF-8</charset>`，确保日志落盘与生产运维全链路兼容。
> 10. **分布式防重与切面限流原子性红线 (Concurrency & Rate Limiting)**：
>    - **严禁 Check-Then-Act 防重**：`@AvoidRepeatableCommit` 切面必须采用 Redis 原子的 `setIfAbsent`（`SET ... NX PX`）抢占分布式排他锁，坚决杜绝“先 get 判空再 setEx”的竞态逻辑，防范瞬时双击穿透；
>    - **限流 Key 必须绑定 URI 隔离路由**：`@AccessLimit` / `@SeckillLimit` 切面中的 Redis Key 必须绑定具体 `requestURI`（`uri + ":" + ip`），严禁仅以单一客户端 IP 作为键，杜绝不同业务接口限流配额发生全局串扰与挤占；
>    - **计数器与过期时间原子协同**：限流计数必须通过原子递增并在初次生成 Key 时绑定 TTL（`incrementWithExpire`），严禁非原子先读后加，严禁遗漏过期时间引发永久闭锁。
> 11. **生产环境严禁使用阻塞式 Redis `KEYS *` 命令 (Redis Non-blocking SCAN)**：
>    - 生产环境中**坚决杜绝调用 `redisTemplate.keys(...)` 或在任何业务链路中执行 `KEYS *`**；
>    - 凡涉及按前缀/通配符批量检索 Redis 键，必须通过 `RedisUtils.scan(...)` 或底层 `redisTemplate.scan(ScanOptions)` 基于游标进行非阻塞分批迭代，并使用 try-with-resources 确保游标安全关闭，彻底杜绝单线程 Redis 事件循环被阻塞导致的集群级超时雪崩。
> 12. **IP 地理库懒加载与微服务堆内存保护规约 (`IpUtils`)**：
>    - `ip2region.xdb`（11MB+）等大体积资源库**严禁在类加载时静态常驻全量堆内存**，必须通过双重检查锁定（DCL）实现按需延迟加载；
>    - 仅解析 HTTP 请求头（`getIpAddr`）的高频链路必须做到 0 额外堆开销与 0 I/O 阻塞，杜绝非城市解析服务（如 OSS、Finance、Product、AI 等）在生产 `-Xmx384m` 预算下被无谓吞噬堆内存。
> 13. **基础通用线程池容量与背压保护规约 (`AsyncExecutorConfig`)**：
>    - 基础设施层默认线程池（`ThreadPoolTaskExecutor`）队列容量必须合理配置（推荐 `>= 200`），拒绝策略必须配置为 `CallerRunsPolicy`（由调用方线程同步兜底执行），**严禁使用粗暴丢弃或抛异常策略（`AbortPolicy`）**，确保突发流量下异步任务绝不丢失；
>    - 线程前缀必须带有清晰的组件命名空间（如 `common-async-`），便于日志检索与 JVM 线程 Dump 排查；必须开启 `setWaitForTasksToCompleteOnShutdown(true)` 保证优雅停机。
>    - **分布式链路追踪透传红线**：所有注册至 Spring 容器的 ThreadPoolTaskExecutor 必须显式挂载 TaskDecorator（统一使用 com.alex.common.utils.trace.MdcTaskDecorator），在父线程抓取 TraceIdContext 与 SLF4J MDC 诊断上下文并在子工作线程注入，子线程退出时强制执行 clear() 彻底清空，杜绝异步调用断链与工作线程复用污染。
> 14. **Jackson 全局定制与 Spring Boot 自动配置共存规约 (`LocalDateTimeFormatConfig`)**：
>    - 统一时间日期格式（`yyyy-MM-dd HH:mm:ss` 等）与 JSR-310 扩展必须通过 `Jackson2ObjectMapperBuilderCustomizer` 进行声明式定制；
>    - **严禁在基础设施类中粗暴声明 `@Bean public ObjectMapper`**，防止覆盖并破坏 Spring Boot 原生自动配置、参数命名策略与各微服务定制的序列化器（如 Long2String 安全注解）。
> 15. **Redis 常量类纯洁性与业务魔法数字隔离红线 (`RedisConstants`)**：
>    - `RedisConstants` 仅限存放 Redis 分布式锁、缓存前缀及分隔符，**严禁放置通用数字字面量（如 `NUM_ONE`、`NUM_FIVE`）**；
>    - 业务层重试上限（如登录失败次数限制）或集合初始容量，必须在业务模块自身常量中显式定义，杜绝跨领域误用产生隐式耦合。
> 16. **统一时间日期处理与时区安全红线 (`DateUtils` 规范)**：
>    - **严禁裸调原生无时区 API**：坚决杜绝在业务代码中直接调用 `LocalDate.now()` 或 `LocalDateTime.now()`（不传参数），避免触发 SonarQube `java:S6888` 告警，并彻底消除微服务在容器化部署（如 Docker 镜像默认 UTC 时区）下因操作系统隐式时区差异导致的“跨天/跨月数据漂移”隐患；
>    - **统一收口至 `DateUtils` 基础底座**：凡需获取当前系统时间或格式化日期字符串，必须统一优先使用 `common_core` 中的 `com.alex.common.utils.date.DateUtils`（如 `DateUtils.now()`、`DateUtils.getNowTimeStr(...)`）；
>    - **复用预编译格式化器常量**：时间格式化必须复用 `DateUtils` 中已预编译且线程安全的静态常量（如 `DateUtils.FORMATTER_YYYY_MM`、`DateUtils.FORMATTER_YYYY_MM_DD`、`DateUtils.FORMATTER_YYYY_MM_DD_HH_MM_SS`），严禁在业务请求链路中反复动态创建 `DateTimeFormatter.ofPattern("...")` 产生额外的解析开销与内存垃圾。
> 17. **SonarQube 静态代码质量与语法防御红线**：
>    - **少分支 Switch 简化 (`java:S1301`)**：对于仅包含 1 或 2 个 Case 的 `switch` 结构，必须重构为简洁的 `if-else` 分支，降低认知复杂度；
>    - **Switch 语句防御性 Default 分支 (`java:S131`)**：对于多分支 `switch` 语句，必须显式提供 `default` 异常抛出或防御性兜底分支，避免遗漏未知枚举/状态引发静默失效；
>    - **线程中断标志完整性保护 (`java:S2142`)**：涉及 `Thread.sleep(...)` 的定时轮询或降级休眠，必须显式捕获 `InterruptedException`，并在异常块中调用 `Thread.currentThread().interrupt()` 恢复中断标志或再次抛出，杜绝掩盖线程中断请求引发线程泄漏或无法优雅停机。
> 18. **Spring 容器多构造函数必须显式标注 `@Autowired`**：
>    - 当 Spring 管理的 Service 或 Component 类中声明了**两个及以上构造函数**（例如为了轻量单元测试重载了少参构造函数）时，**必须且仅能在预期的容器注入构造函数上显式标注 `@Autowired`**；
>    - 严禁仅在形参上标注 `@Autowired(required = false)` 而遗漏构造函数本身的 `@Autowired`，否则 Spring 无法判定目标构造函数并回退至无参构造函数导致 `NoSuchMethodException: <init>()` 启动失败崩溃。
> 19. **公共底座自动配置类全限定名严格校验规约 (`spring.factories`)**：
>    - `alex_miaosha_common/common_core` 中在 `META-INF/spring.factories` 注册 `EnableAutoConfiguration` 时，类全限定名必须与源码包路径 100% 字符对齐；
>    - 严禁拼写错误或遗漏子包层级（如将 `multilevel.MultiLevelCacheAutoConfiguration` 写为 `cache.MultiLevelCacheAutoConfiguration`），防范全微服务类路径读取中断。

## 3. 生产容器与 768M-JVM 调优红线

在生产环境严格限制 **768 MiB** 内存配额下：
- **JVM 调优统一参数**：
  ```bash
  -Xms384m -Xmx384m -XX:MaxMetaspaceSize=128m
  ```
  预留 384MB 空间给 Metaspace、DirectBuffer 及操作系统栈，彻底避免被 Linux OOM Killer 强杀；
- **文件流式操作**：所有文件存取接口一律使用 `InputStream` / `OutputStream` 流式分块传输，**严禁将文件全量读入 `byte[]` 数组**；
- **Drone 自动化部署顺序**：`finance ➔ user ➔ product ➔ oss ➔ ai ➔ gateway`（入口网关必须最后发布）；
- **Drone 宿主机日志统一挂载映射**：
  所有生产微服务容器的 `/logs` 目录统一映射至宿主机持久化目录：
  ```text
  宿主机路径: /usr/local/soft/alex_miaosha/drone/alex_miaosha/logs/
  ├── alex-gateway-prod/       # Gateway 网关服务日志 (:30001)
  ├── alex-user-prod/          # User 用户权限服务日志 (:30006)
  ├── alex-product-prod/       # Product 商品库存服务日志 (:30007)
  ├── alex-finance-prod/       # Finance 财务流水服务日志 (:30008)
  ├── alex-oss-prod/           # OSS 对象存储服务日志 (:30009)
  └── alex-ai-prod/            # AI 智能分析微服务日志 (:30010)

## 4. SonarQube 质量红线与代码安全规约

- **并发中断标志位守卫 (`java:S2142`)**：
  - 在捕获 `InterruptedException` 时，严禁直接捕获后仅打印日志或单纯抛出包装异常而丢失中断信号；
  - 必须在抛出前或处理中显式调用 `Thread.currentThread().interrupt()` 恢复当前线程的中断状态，确保上层反应式或线程池管理组件能正常感知中断请求。
- **公共静态成员不可变性 (`java:S1170`)**：
  - 全局 Redis 键单例（如 `LoginKey`、`CommonKey`、`AccessKey` 等）必须声明为 `public static final`；
  - 严禁省略 `final` 修饰符，防止在并发场景下或第三方反射调用中被全局篡改，引发缓存击穿或跨租户键冲突。
- **跨端加解密契约守卫 (`java:S3329`)**：
  - PC 端前端（`alex_miaosha_front`）与移动端在用户密码通信上采用 AES-CBC 预共享 IV 契约；
  - 后端 `AESUtils` 必须维持现有预共享协议并标注 `@SuppressWarnings("java:S3329")`，严禁在未协同改造所有前端/移动端契约的情况下单方面修改为动态 IV。

## 5. 公共底座架构与性能规范 (`common_core`)

- **堆内存常驻释放与懒加载模式 (`IpUtils`)**：
  - 静态资源库（如 11MB 的 `ip2region.xdb`）严禁在类加载 `static {}` 块中无条件全量读取常驻堆内存；
  - 必须采用**双重检查锁定 (DCL) 延迟懒加载**，仅当真正调用离线物理地址解析时才加载缓冲区。常用高频仅解析 HTTP Header 的 `getIpAddr(request)` 必须保持 0 堆内存开销，直接为 768M 生产容器释放核心内存。
- **通用异步线程池防丢弃规范 (`AsyncExecutorConfig`)**：
  - 公共异步线程池拒绝策略统一设定为 `ThreadPoolExecutor.CallerRunsPolicy`（队列满时回退由调用方主线程同步执行），严禁使用 `AbortPolicy` 导致关键业务任务无故抛错丢弃；
  - 队列容量须结合内存配额合理设定（默认 200），线程池前缀规范化为 `common-async-`。
- **非侵入全局 JSON 格式化规约 (`LocalDateTimeFormatConfig`)**：
  - 严禁通过 `@Bean public ObjectMapper objectMapper()` 强行 `new` 实例覆盖 Spring Boot 默认配置体系（会导致命名策略、特性模块等全局丢失）；
  - 必须通过实现 `Jackson2ObjectMapperBuilderCustomizer` 接口对日期、时区（`yyyy-MM-dd HH:mm:ss`, `GMT+8`）进行非侵入式定制。
- **常量定义语义纯洁性 (`RedisConstants`)**：
  - 常量类必须职责单一，禁止将通用数字（如 `NUM_ONE`, `NUM_FIVE`）塞入特定中间件常量（如 `RedisConstants`）供业务层初始化或重试控制；
  - 所有公共静态常量必须显式声明 `public static final`。

## 6. 实体模型与持久层分层规约 (Entity & Persistence Standards)

- **实体继承与基础审计字段**：
  - 所有业务实体必须 `extends BaseEntity<T>`；
  - 严禁在子类重复定义 `id`、`creator`、`create_time`、`updater`、`update_time`、`operator`、`operate_time`、`deleter`、`delete_time`、`is_delete` 等审计字段；
  - 业务表名统一以 `_info_t` 结尾，字段命名统一使用 `snake_case`，时间字段统一使用 `LocalDateTime`；
  - 逻辑删除统一复用 `@TableLogic` 对应的 `is_delete`，严禁新增业务专用的 `delete_flag`。
- **接口分层与契约对象边界**：
  - Controller 只能接收 DTO / Query，并返回 VO 或统一 `Result` 对象，**严禁直接对外返回 Entity 实体**；
  - Service 层使用 `IService`、`ServiceImpl`、`LambdaQueryWrapper`、`LambdaUpdateWrapper` 与 `Page`；
  - 严禁在 ServiceImpl 中直接拼接硬编码字符串 SQL，复杂聚合查询优先封装为清晰语义的 Mapper XML / 注解方法；
  - 涉及租户与家庭范围的列表、详情、编辑、删除、统计、导出，必须带 `org_id` 数据隔离条件。
- **数据权限作用域与角色对齐 (`@DataPermission`)**：
  - `@DataPermission.scope()` 统一使用独立枚举 `DataPermissionScope`：`USER_OWNER` / `USER_IDS`（管理员机构成员子查询、普通用户本人）、`ORG_SHARED`（礼尚往来家庭组共享）、`ORG_ID`（机构树，管理员扩子孙）；
  - 角色判定统一通过 `RbacRoleCodes` 工具方法（`isSuperRole` / `isAdminRole` / `isUserRole`）：超级管理员角色主编码为 `super_super`，系统同时在 `RbacRoleCodes.isSuperRole` 兼容别名 `super_admin` 并已在 `isAdminRole` 中显式排除超管别名防止误判为普通机构管理员；机构管理员支持 `admin` 及以 `_admin` 结尾的角色（如 `org_user_admin`、`family_admin`、`gift_admin` 等），普通用户支持 `user` 及以 `_user` 结尾角色，严禁业务直接用字符串 `contains` 模糊判断。
- **Stream 空安全与泛型编译警告**：
  - 在 Stream 映射时，避免直接使用可能带有 `@Nullable` 属性的实例方法引用（如 `String::trim`），推荐使用显式的 Lambda 表达式或带非空校验的表达式（如 `.map(s -> s == null ? "" : s.trim())`），防止编译器报 `Null type safety` 警告或异常。

## 8. 微服务边缘网关 Gateway 动态路由、流控限流与安全代理规约 (`alex_miaosha_gateway`)

### 1. 动态服务路由与多环境映射规约
- **服务前缀剥离与转发**：
  - 各业务微服务统一在网关配置独立的路径前缀（`user -> /am-user/**`, `finance -> /am-finance/**`, `product -> /am-product/**`, `oss -> /am-oss/**`, `ai -> /am-ai/**`）；
  - 必须配置 `StripPrefix=1`，确保转发给下游微服务时剥离边缘网关前缀；
  - 路由目标统一采用 Nacos 服务发现负载均衡协议 `lb://alex-{service}-{env}`；
- **长连接与超时配额**：
  - 全局连接超时统一配置为 `connect-timeout: 5000`（5秒）；
  - 响应超时统一配置为 `response-timeout: 180s`（180秒），专门保障大模型长文本流式推理（SSE）与大型 Excel/报表数据导出不被网关过早截断。

### 2. 真实客户端 IP 穿透与多维度限流 (`RateLimiterConfiguration`)
- **真实客户端 IP 穿透解析**：
  - 网关直接面对 Nginx / SLB / CDN 等多层反向代理，严禁直接使用底层 Socket 连接的 `RemoteAddress` 进行 IP 限流（会导致整个代理节点下的所有用户共享限流额度）；
  - 必须按优先级提取：`X-Forwarded-For`（多级代理逗号分隔时取首个 IP） ➔ `X-Real-IP` ➔ `Proxy-Client-IP` ➔ `WL-Proxy-Client-IP` ➔ `RemoteAddress.getHostAddress()` ➔ `"unknown"`（防 NPE 兜底）；
- **用户凭证与 API 限流解析**：
  - 用户限流 KeyResolver：从 `audience.getTokenHeader()`（默认 `Authorization`）提取 Bearer Token，未登录时回退为 `"anonymous"`；
  - API 路径限流 KeyResolver：提取规范请求路径 `request.getPath().value()`。

### 3. 安全鉴权、协议协商与加密旁路规约 (`GatewayFilter`)
- **双重白名单机制**：
  - `docWhiteList`（`/swagger-resources/**`、`/doc.html`、`/**/v3/api-docs/**` 等）：直接通过 `chain.filter(exchange)` 放行，不请求远程 `UserApi`，不执行响应加密；
  - `whiteList`（如 `/am-user/api/v1/user/login`）：免 Token 鉴权放行，但其返回报文依然按照客户端协议协商执行加密输出；
- **未认证 403 阻断契约**：
  - 缺少 Token 或鉴权失败时，严禁调用下游微服务 FilterChain；
  - 统一构造 `{"success":false,"code":403,"data":"请先登录！"}` 并根据客户端协议版本（`X-Crypto-Version: 1.0/2.0`）加密为二进制报文输出，响应头回显对应版本号；
- **SSE 流式与大文件加密旁路 (Bypass Encryption)**：
  - 流式长连接（`text/event-stream`、`/am-ai/api/v1/ai/chat/stream` 等）与二进制大文件下载（`application/octet-stream`、Excel/PDF/Word 等）**必须跳过网关响应加密缓冲**（`shouldSkipResponseEncryption`）；
  - 严禁将 SSE 数据块缓存为整包密文，确保流式打字机效果与大文件下载性能无损。

## 十、 用户中心 RBAC 动态权限、单有效机构事务与 Redis 登录上下文防污染规约

### 1. VO 大数雪花 ID 序列化与反射契约锁
- **树结构父级关联大数保护**：
  - 组织机构 VO `OrgInfoVo` 中的 `parentId` 必须强制标记 `@JsonSerialize(using = Long2StringSerializer.class)`，杜绝树形节点低位数字精度丢失；

  - 反射契约锁排查所有非静态 `Long` 字段，排除 `serialVersionUID` 等常量字段。

### 2. 菜单树 Redis 全局共享缓存隔离与内存防污染
- **管理端树形接口契约**：
  - 管理端 `MenuInfoServiceImp#getTree` 必须走带 `@DataPermission` 的 scoped `getList` 在内存动态拼装 `children`；
  - 严禁调用 `getListAll`，严禁读写 `LoginKey:login:in:menu_all_tree`（该键专供登录全量缓存使用）；
- **全量与过滤查询缓存隔离**：
  - 仅在 `isFullQuery`（`status=1` 且无名称/路径过滤关键字）时触发 `menu_all_tree` 缓存读写；
  - 任何带关键字的筛选查询严禁读写共享缓存，防止条件过滤污染全量菜单树；
- **内存不可变性与深克隆机制**：
  - 非超管权限过滤菜单时，必须通过 `new MenuInfoVo()` 复制属性并组装独立的 `children`；
  - 严禁原地修改原始共享对象的 `children` 列表，防止 Redis 共享对象在 JVM 堆内存中被污染。

### 3. 单有效机构事务与主动逐出失效机制
- **单用户唯一有效机构语义**：
  - `OrgUserInfoServiceImp#assignSingleOrg` 统一处理有效机构分配，必须在原子事务内将旧有效机构置为 `status=0`，新机构置为 `status=1`；
  - 成功提交后，必须主动调用 `PermissionContextCacheService#invalidate(userId)` 逐出 Redis `permission_context:{userId}` 缓存，绝不依赖 1 小时 TTL 兜底；
  - 调岗事务失败或回滚时，严禁提前或错误清理缓存；
- **新增拦截与历史孤儿行清理**：
  - `addOrgUserInfo` 显式传入非有效状态（如 `status=0`）时，直接抛出 `PARAM_ERROR` 业务异常，拒绝伪调岗侵入；
  - `updateOrgUserInfo` 激活已有行时通过 `activateViaAssign` 物理清理遗留的历史失效孤儿行，保证 `(userId, orgId)` 记录唯一性；
  - 超过 `MAX_INACTIVE_HISTORY` (5) 条失效记录时自动修剪清理，防止历史行无限堆积。

### 4. RBAC 动态权限上下文构建与瘦身降级机制
- **多角色权限聚合与第一有效机构**：
  - `UserPermissionContextServiceImpl#buildContext` 异步并发提取机构、角色与菜单树，合并多角色绑定的权限码并去重保序；
  - 提取用户关联列表中的第一有效机构作为登录上下文中的 `orgInfo`；
  - 角色包含 `super_super` 时标记为超级管理员，菜单全量直通，跳过权限码过滤裁剪；
- **缓存命中瘦身模式**：
  - `includeMenus=false` 时调用 `copyWithoutMenus` 剥离菜单树，降低内存与传输带宽，且严禁清空原 Redis 缓存对象的菜单列表；
- **高可用平滑降级**：
  - Redis 读写抛出网络异常或连接超时时，捕获异常记录日志，业务主链路平滑降级为全量动态计算，确保用户中心高可用。

## 十一、 AI 智能分析微服务多模型双路由、Markdown自适应清洗与配额熔断降级规约

### 1. LLM 响应 Markdown 围栏自适应清洗与容错规约 (`AbstractOpenAiCompatibleAiEngine`)

  - 调用各类大模型（DeepSeek、商汤 SenseNova、OpenAI 兼容协议）时，模型可能在 JSON 结构化数据外包裹 ````json\n...\n```` 或 ````\n...\n```` 标记；

  - 遇到无法解析的自由文本或畸变断句，自动优雅降级为纯文本 summary 输出，`keyPoints` 保留为空列表，杜绝向前端抛出 500 异常。

  - 当大模型服务不可用或网络超时且 `ai.fallback.enabled=true` 时，自动平滑切换至本地 `ruleBasedAiEngine`，引擎标识标记为 `rule-based(fallback)` 并在 summary 中追加回退说明；

### 3. Redis 语义指纹缓存与分钟/日级配额熔断降级 (`AiAnalyzeServiceImpl`)
- **确定性 SHA-256 语义指纹**：
  - 提取 `bizType + content + sorted(context)` 计算 SHA-256 哈希作为缓存键（`AiCacheKey:analyze:{bizType}:{hash}`），TTL 统一为 2 小时；
  - 缓存命中时返回并标记 `engine="redis-cache"`，0 远程引擎调用，免扣减调用方额度；
- **多级限流与轻量降级**：
  - 分钟限流阈值：15 次/分；
  - 单日配额阈值：150 次/天；
  - 超过阈值时，系统**绝不向调用方抛出 429 报错**，而是自动平滑切换至 `rule-based(quota-degraded)`，并在 summary 中追加友好降级提示语，保障用户业务不中断。

### 4. SSE 流式传输生命周期与连接回收契约 (`AiSseEventWriter` & `AiAnalyzeController`)
- **标准事件协议时序**：
  - 流式响应采用 `MediaType.TEXT_EVENT_STREAM_VALUE`；

  - 异常时通过 `error` 事件回传业务错误码并关闭流；
- **连接超时与断开回收**：
  - 默认流式超时时间为 120,000ms（2分钟）；
  - 客户端提前断开连接导致底册 `IOException` 时，捕获并调用 `completeWithErrorQuietly` 释放线程与网络资源，杜绝连接泄露。

## 十二、 公共底座 Common 异常体系规范、分布式并发切面与基础工具健壮性规约

### 1. 全局异常处理与精确错误码映射保真 (`GlobalExceptionHandler`)
- **系统基础异常（SystemException）精准捕获**：
  - 必须显式注册 `@ExceptionHandler(SystemException.class)`，禁止掉入兜底 `Exception.class` 导致业务错误码丢失；
  - 遇到参数错误（如 `PARAM_ERROR`）映射为 HTTP 400，遇到系统错误透传其具体的业务错误码（如 `500102` 系统不可用），禁止一律暴力转换为 500；
- **参数校验与反序列化友好提示**：
  - `BindException` 提取所有字段的 `defaultMessage` 进行聚合，以逗号分隔返回，状态码固定为 400；
  - `HttpMessageNotReadableException` 拦截并返回友好提示 `"请求参数格式有误，请检查数据格式"`，杜绝底层 Jackson 堆栈泄露；
- **领域异常保真**：
  - 各微服务垂直领域异常（`UserException`, `FinanceException`, `AiException`, `FileException`）保持独立捕获通道，严格透传对应的业务错误码与错误信息。

### 2. 分布式并发切面防重复提交与限流规范 (`AvoidRepeatableCommitAspect` & `AccessLimitAspect`)
- **Token 优先与 IP 兜底防重提交**：
  - `AvoidRepeatableCommitAspect` 优先从请求头提取 `token` 作为唯一凭证，无 Token 时以真实客户端 IP 兜底；
  - 参数指纹计算对 `MultipartFile` 参数提取文件名与文件大小，防止默认对象哈希值不稳定导致防重失效；
  - 基于 Redis `setIfAbsent` (SET NX PX) 执行强原子抢占，失败时立即返回 `ResultEnum.REPEAT_COMMIT`，根除 Check-Then-Act 竞态击穿；
- **接口频次原子限流与 URI 隔离**：
  - `AccessLimitAspect` 生成的 Redis 键严格遵循 `URI + ":" + IP` 格式，彻底隔离不同接口配额；
  - 使用 `redisUtils.incrementWithExpire` 实现原子递增并保证在首次访问时写入 TTL，超限时返回 `ResultEnum.ACCESS_LIMIT_REACHED` (429 对应码)。

### 3. 大数雪花 ID 序列化契约与 null 安全规范 (`Long2StringSerializer`)
- **前后端防精度截断契约**：
  - 后端所有 19 位雪花算法生成的主键、父级 ID 等 Long 字段，在 VO 中必须声明 `@JsonSerialize(using = Long2StringSerializer.class)`；
  - 集合类型 Long 字段（如 `List<Long>`）必须声明 `@JsonSerialize(contentUsing = Long2StringSerializer.class)`；
- **Null 安全规范**：
  - `Long2StringSerializer` 必须显式处理 null 分支，调用 `jsonGenerator.writeNull()`，严禁在 null 时抛出 NPE 或遗漏字段键名。

### 4. 高安全加解密与日期工具并发安全规范 (`AESGcmUtils` & `DateUtils`)
- **AES-GCM (AEAD) 高安全模式**：
  - 规范严格遵循 NIST SP 800-38D：每次加密使用 `SecureRandom` 生成全新的 12 字节 IV (Nonce)，认证标签长度为 128 位 (16 字节)；
  - 密文报文封装：`Base64(12 字节 IV + GCM 密文含 Tag)`；
  - 解密时若密文被单字节篡改，底层自动抛出 `AEADBadTagException` 拒绝解密，杜绝重放与填充攻击；密文小于 28 字节时前置防御拦截；
- **时区安全与静态 DateTimeFormatter 复用**：
  - 严禁在业务代码中直接调用 `LocalDate.now()` 或 `LocalDateTime.now()`；
  - 统一使用 `DateUtils.now()`（绑定 `ZoneId.systemDefault()`），并复用预编译的静态常量 `DateUtils.FORMATTER_YYYY_MM_DD_HH_MM_SS` 等，确保多线程并发格式化 100% 线程安全。

## 十三、 微服务网关 Gateway 全局统一异常处理、CORS 暴露头与认证短路优化规约

### 1. 网关全局 JSON 异常处理器规约 (`GatewayJsonErrorWebExceptionHandler`)
- **优先级与组件定义**：
  - 网关必须注册实现 `ErrorWebExceptionHandler` 的异常处理器，并通过 `@Order(Ordered.HIGHEST_PRECEDENCE)` 置于最前，彻底替代 Spring Boot 原生 Whitelabel Error Page；
- **标准异常映射契约**：

  - `ConnectException` / HTTP 503 $\rightarrow$ 状态码 503，输出 `{"code":"503","message":"目标微服务不可用或网络不可达，请稍后重试！","data":null}`；
  - `TimeoutException` / HTTP 504 $\rightarrow$ 状态码 504，输出 `{"code":"504","message":"下游微服务响应超时，请稍后重试！","data":null}`；
  - 其他内部异常 $\rightarrow$ 状态码 500，输出标准 Result 结构；
- **响应头保真与协议回显**：
  - 必须显式设置 `Content-Type: application/json;charset=UTF-8`；
  - 若客户端请求携带 `X-Crypto-Version: 2.0`，在异常响应头中回显 `X-Crypto-Version: 2.0`。

### 2. 网关过滤器认证短路与超时熔断保护 (`GatewayFilter`)
- **空 Token 快速短路**：
  - 提取请求头 Token 后，若 `StringUtils.isBlank(token)`，必须直接调用 `out(exchange)` 返回 403 阻断，**严禁向下游用户微服务发起远程 Feign RPC**，杜绝未登录恶意流量对认证服务的冲击；
- **远程 RPC 限时熔断**：
  - 远程认证调用必须设置超时上限（`completableFuture.get(3, TimeUnit.SECONDS)`）；
  - 发生超时或网络异常时，捕获异常并安全降级返回 403，绝不挂死 Netty 工作线程，杜绝网关雪崩。

### 3. CORS 跨域响应头暴露规范 (`GlobalCorsConfig`)
- **关键响应头暴露清单**：
  - 跨域过滤器必须显式通过 `addExposedHeader` 暴露以下关键 Header：
    1. `EncryptionUtils.HEADER_CRYPTO_VERSION` (`"X-Crypto-Version"`，支持前端加解密协议协商)；
    2. `HttpHeaders.CONTENT_DISPOSITION` (`"Content-Disposition"`，支持前端导出/下载文件提取文件名)；
    3. `HttpHeaders.AUTHORIZATION` 与 `"token"`（支持前端跨域读取并刷新认证令牌）；
- **预检请求长效缓存**：
  - 跨域预检请求 `setMaxAge(18000L)`（5 小时），并显式 `setAllowCredentials(true)`。

## 十四、 财务微服务 Finance 记账分析、预算边界与跨成员数据权限规约

### 1. 月度零花钱预算七点法边界与生命周期规约 (`FinanceBudgetInfoServiceImpl`)

- **趋势计算除零安全**：
  - 环比（MoM）与同比（YoY）趋势计算（`calculateTrend`）在基期为 0 时安全输出 `"+100%"` / `"-100%"` / `"0.0%"`，严禁触发除零异常或生成 `NaN`；
- **跨年月份回溯安全性**：

  - `belongTo <= 0` 统一归一化为 null，向下游 Mapper 传 null 以汇总家庭全员流水，杜绝无效 ID 过滤。

### 3. 财务流水跨家庭成员垂直数据权限隔离规约 (`FinanceInfoServiceImp`)

  - S3 Object Key 必须遵循统一的三段式正斜杠组织规范：`{safeType}/{yyyy-MM-dd}/{safeBaseName}_{timestamp}.{safeSuffix}`；
  - 强制全链路使用 S3 虚拟目录正斜杠 `/`，严禁使用操作系统的反斜杠 `\`。

### 3. S3 预签名直链、免签持久直链与防盗链时效规约 (`BaseS3Template`)
- **公私分级直链策略**：

  - 当 `isPublic == false` 或未传（`null`）时，遵循安全防御基线，一律调用 MinIO `getPresignedObjectUrl` 签发有时效保护的临时预签名直链（时效固定为 3600 秒 / 1 小时）；
- **外部域名映射与 URL 路径分段编码**：
  - 若系统配置了 `oss.publicUrl`（或 CDN 域名），直链生成时自动安全替换 MinIO 内部局域网 IP 与端口为对外统一域名；
  - 对象键中包含中文、空格或特殊字符时，采用 `encodePathKey` 按路径段执行 URL 编码，保留路径分隔符 `/`，并避免已编码参数产生二次双重转义（如 `%20` 不被转义为 `%2520`）。

## 十六、 系统消息与多业务到期提醒中心质量加固、防越权与定时巡检幂等规约

### 1. 批量删除参数类型防呆与 500 防御规约 (`SysMessageInfoServiceImpl#deleteMessages`)
- **非数字字符串防御**：
  - 接口接收逗号分隔的 `ids` 字符串时，严禁裸调 `Long::valueOf`；必须增加 `NumberFormatException` 捕获并转化为友好提示 `FinanceException.param("删除消息ID格式不正确")`，彻底杜绝恶意传入 `"abc"`、`"1,xyz,2"` 导致的 500 级崩溃；

### 2. 未读消息分类统计汇总对齐规约 (`SysMessageSummaryVo` & `getSummary`)
- **人情回礼备忘独立统计**：
  - `SysMessageSummaryVo` 必须提供 `giftReturnUnread`（人情回礼备忘未读数）字段与 Getter/Setter；

### 3. 跨用户与跨机构水平越权防御规约 (`markRead`, `deleteMessages`, `publishSystemMessage`)
- **已读标记与删除行级鉴权**：
  - `markRead` 与 `deleteMessages` 必须调用 `assertMessageAccessible`：

    - 针对已软删除（`is_delete = 1`）或不存在的消息，安全拦截抛出 `FinanceException.param("消息不存在或已被删除")`；
  - 超级管理员跨用户与跨机构管理放行；
- **发布通知身份防伪**：
  - 非超管用户通过 `publishSystemMessage` 发布个人提醒时，系统强制将其 `userId` 重置绑定为当前操作人 `user.getId()`，`orgId` 锁定为当前机构，严禁篡改入参伪造他人发布或伪造全员系统广播（`userId=0, orgId=0`）。

### 4. XXL-Job 定时巡检幂等、防复活与微信推送降级规约 (`executeRemindJob`)
- **多业务临期巡检与去重防重**：
  - 巡检涵盖四大业务源：礼尚往来事件（提前 1 天/当天举行）、消费券（剩余 0~3 天且余量 > 0）、预付卡/猫超卡（剩余 0~3 天且余额 > 0）、人情回礼备忘（净盈余 >= 800 且超 180 天无互动）；
  - 基于确定性 `dedup_key`（`{bizType}:{bizId}:{subType}:{remindDate}:{userId}`）入库，同一巡检周期内重复触发新增条数恒等于 0（100% 幂等）；
- **防复活契约 (Anti-Resurrection)**：
  - `SysMessageInfoMapper.selectExistingDedupKeys` 查询已存在键时，**绝对不加 `is_delete = 0` 过滤条件**；
  - 用户手动删除消息后，后续调度再次巡检时检测到库内已存在该 `dedup_key`，绝对不重新插入新消息，彻底杜绝已删提醒被定时任务死灰复燃；
- **微信模板推送网络容错与事务隔离**：
  - 新增提醒触发 `weChatService.sendRemindTemplateMessage` 时必须使用 `try-catch` 包裹，微信接口发生超时或故障时安全记录 Warn 日志并降级，严禁因第三方网络波动引发站内信入库事务回滚。

## 十七、 用户中心微服务 Token 刷新、在线时效与密码安全防御规约

### 1. 在线用户会话过期时间防失真规约 (`OnlineUserService`)
- **时间单位严格对齐**：
  - `OnlineUserService#buildOnlineAdmin` 在计算在线会话的 `expireTime` 时，必须严格采用 `DateUtils.addTime(DateUtils.now(), expiration, ChronoUnit.SECONDS)`；
  - 严禁误传为 `ChronoUnit.MICROS`（微秒）或 `ChronoUnit.MILLIS`，确保显示给管理员的会话到期时间与底层 Redis `setEx` 的 TTL 时长（秒级维度）保持绝对一致。

### 2. 用户登出全链路会话原子清理规约 (`TUserServiceImpl#logout`)
- **登出联动清理三部曲**：
  - 用户执行注销登出操作时，服务必须联动清理三大核心 Redis 会话缓存：
    1. `LoginKey.loginUuid`（UUID Token $\rightarrow$ JWT Token 映射键）；
    2. `LoginKey.loginToken`（JWT Token $\rightarrow$ 用户基础数据缓存键）；
    3. `LoginKey.loginOnlineUser`（以 `uuidToken` 标识的在线用户列表记录）；
  - 彻底杜绝注销后在线监控列表残留“幽灵会话”的问题；
- **非法入参快速短路拦截**：
  - 请求头未携带 Token，或其值为 `"undefined"`、`"null"` 时，快速返回 `Result.error(PARAM_ERROR)`，严禁向下穿透误删系统公共缓存。

### 3. 用户资料修改与密码安全防护规约 (`updateTUser` & `resetUserPassword`)
- **常规资料更新排除密码字段**：
  - `TUserServiceImpl#updateTUser` 属性拷贝时必须显式排除密码：`BeanUtils.copyProperties(tUserVo, tUser, "password")`；
  - 杜绝前端编辑个人资料表单时，因携带未加密明文或空白密码意外覆盖数据库已有的加盐散列密文，从而破坏用户登录；
- **密码专用重置接口与加盐防弱密**：
  - 重置/修改密码必须走专用接口（`resetUserPassword`）：
    1. 强校验必须满足 `assertUserAccessible` 租户/机构数据权限，机构管理员严禁跨机构篡改他人密码；
    2. 密码非空且长度不得少于 6 位，拒绝空白字符与简单弱密；
    3. 强制严格按照加盐规范 `BCRYPT_ENCODER.encode(password + username)` 执行加盐散列；
    4. 密码修改成功后，必须立即调用 `permissionContextCacheService.invalidate(userId)` 失效其权限上下文与已有登录态。

### 4. 临近到期 Token 异步刷新并发防雪崩规约 (`TokenRefreshService`)
- **并发刷新互斥锁**：
  - 客户端在高并发请求下临近 Token 刷新窗口时，`TokenRefreshService` 必须利用 Redis 的 `setIfAbsent(LoginKey.loginRefreshLock, uuidToken, "1", 15, TimeUnit.SECONDS)` 加互斥锁；
  - 未能获取锁的并发异步任务静默跳过，严禁重复签发新 Token 与频繁交错删除旧 `loginToken`，彻底杜绝高并发网络抖动下的并发雪崩。

## 十八、 网关微服务全局灰度发布路由、黑名单 IP 动态拦截与跨微服务链路追踪（TraceId）透传规约

### 1. 全局微服务链路追踪 TraceId 生成与双向回写规约 (`TraceIdGlobalFilter`)
- **最高执行优先级**：
  - `TraceIdGlobalFilter` 必须设置为 `Ordered.HIGHEST_PRECEDENCE`（保证在整个网关过滤器链的最前端运行）；
- **凭据生成与保真透传**：
  - 提取客户端请求头中的 `X-Trace-Id` 或 `X-Request-Id`；若不存在或为空，系统自动生成 32 位全局唯一 Hex TraceId（`UUID.randomUUID().toString().replace("-", "")`）；
  - 向下游微服务请求头中注入 `X-Trace-Id`，确保 User、Finance、OSS、AI 等微服务日志具备统一跟踪凭据；
  - 在网关对外响应头中 100% 回写 `X-Trace-Id`，以便前端错误上报与 Sentry 告警快速串联排查。

### 2. 动态 IP 黑名单快速短路拦截规约 (`IpBlacklistGlobalFilter`)
- **真实外网 IP 提取策略**：
  - 兼容多级反向代理与 CDN 场景，按序从 `X-Forwarded-For`（逗号分隔首个非未知外网 IP）、`X-Real-IP`、`Proxy-Client-IP`、`RemoteAddress` 中解析客户端真实 IP；
- **快速阻断防穿透**：
  - 过滤器优先级紧随 TraceId 之后（`HIGHEST_PRECEDENCE + 1`），先于业务鉴权与加解密；
  - 命中黑名单（支持单 IP 及 `10.0.0.*` 通配网段）时，直接返回 HTTP 403 Forbidden 与统一 JSON 响应（`{"code": 403, "message": "IP已被安全封禁，禁止访问: ...", "success": false}`）；
  - 绝对不向下游微服务透传，绝不调用下游 User 微服务发起远程 Feign 认证 RPC，秒级卸载恶意流量。

### 3. 全局灰度发布流量染色与负载均衡元数据规约 (`GrayReleaseGlobalFilter`)
- **灰度标签自动提取与规范染色**：
  - 识别客户端请求头 `X-Gray-Tag`（或配置的灰度头，如 `X-Canary-Channel`）；
  - 若携带有效灰度标签或特定版本号（如 `v2.5.0`），自动向下游微服务注入 `X-Route-Tag: gray` 与 `X-Service-Version: {version}`；
  - 未携带灰度标记时，规范注入 `X-Route-Tag: default` 与 `X-Service-Version: default` 实现平滑降级兜底；
  - 过滤器优先级早于常规业务过滤器，保证微服务间负载均衡与 Nacos 路由元数据就绪。

## 二十、 微服务间 Feign 远程调用熔断降级、TraceId 透传与防呆规约

### 1. 全链路凭据与灰度标签 100% 透传规约 (`FeignConfig`)
- **Web 请求头保真透传**：
  - `FeignConfig` 实现 `feign.RequestInterceptor`；
  - 在标准 Servlet 线程中，完整提取并透传以下请求头至下游微服务：
    1. `Authorization`（安全身份认证凭据）；
    2. `X-Trace-Id`（全局分布式链路追踪 ID）；
    3. `X-Request-Id`（客户端单次请求唯一幂等标识）；
    4. `X-Gray-Tag` / `X-Route-Tag`（网关灰度发布染色与路由版本标签）；
- **非 Web 上下文与异步线程链路闭环**：
  - 在异步线程池（`@Async`、`CompletableFuture`）或调度任务（`XXL-Job`）中，`RequestContextHolder` 必为 null；
  - 拦截器必须回退检查 SLF4J `MDC` 中的 `traceId` / `X-Trace-Id`；
  - 若 `MDC` 仍无 TraceId，必须自动生成 32 位 Hex TraceId 保底，确保微服务发出的所有 Feign RPC 出口流量 100% 具备全链路凭据，彻底杜绝调用链路断流。

### 2. Feign 超时与非幂等重试防呆规约 (`Request.Options` & `Retryer`)
- **超时合理设定**：
  - 必须显式声明并注册 `Request.Options` Bean，默认连接超时（Connect Timeout）设为 5000ms，读取超时（Read Timeout）设为 10000ms；
  - 严禁无超时或无限阻塞调用，防止目标服务假死挂起上游 Tomcat 业务工作线程池；
- **显式禁用隐式重试 (`Retryer.NEVER_RETRY`)**：
  - 必须显式声明并注册 `Retryer.NEVER_RETRY`；
  - 在分布式微服务架构中，对于涉及记账扣减、资产划转、发信通知等非幂等写操作，底层网络的隐式重试会导致灾难性的重复扣费或脏数据，重试必须由业务层显式基于幂等性控制。

### 3. 微服务间统一错误解码防呆规约 (`FeignErrorDecoder`)
- **业务 Result 结构精准解码**：
  - 统一实现并注册 `FeignErrorDecoder`（实现 `feign.codec.ErrorDecoder`）；
  - 下游微服务返回 4xx/5xx 时，智能读取解析 `Response.body()` 中的 JSON 报文；
  - 若能解析出结构化的 `Result<T>` 报文（包含 `code` 和 `message`），精准提取并封装为 `SystemException(code, "[Downstream:method] " + msg)`，保留下游微服务的原始业务提示与错误码，严禁将业务校验失败吞没为模糊的系统 500 异常；
- **基础设施故障状态码优雅映射**：
  - 针对下游 404（接口不存在），统一映射为 `SYSTEM_NO_AVAILABLE (500102)`；
  - 针对下游 502/503/504（服务宕机/超时不可达），统一映射为 `SYSTEM_BUSY (500101)`。

### 4. OpenFeign `FallbackFactory` 契约合规与优雅降级规约
- **严禁注解属性混淆**：
  - 若类实现的是 `FallbackFactory<Api>`，`@FeignClient` 注解必须使用 `fallbackFactory = MyFallbackFactory.class`；
  - **严禁误写为 `fallback = MyFallbackFactory.class`**，否则 OpenFeign 校验接口继承失败导致服务启动炸裂；
- **严禁在 `create()` 内部直接粗暴抛错**：
  - `FallbackFactory#create(Throwable cause)` 必须返回一个**非空的 API 接口代理实例**；
  - 接口各方法实现中，记录包含目标服务名、方法名与 `cause.getMessage()` 的链路级错误日志，并返回规范的结构化降级报文（如 `Result.error(SYSTEM_NO_AVAILABLE.getCode(), "...")`），提供优雅降级体验。

### 1. 微服务本地线程上下文与 MDC 生命周期规约 (`TraceIdContext` & `TraceIdFilter`)

## 二十二、 Druid 数据库连接池防泄漏、慢 SQL 审计与 WallFilter 防注入规约

### 1. 连接池防泄漏机制与强制回收规约 (`removeAbandoned`)
- **开启强制泄漏回收**：
  - 各微服务 Druid 连接池必须开启 `removeAbandoned = true`，当借出的物理连接占用超过阈值未主动归还时，由连接池内部后台守护线程自动强制回收；
  - `removeAbandonedTimeout` 默认设定为 180 秒（3 分钟），严禁设置为 0 或过小值，确保常规正常业务事务不被误杀；
  - 彻底规避长事务挂死、第三方大文件流式导出异常未关闭、或下游超时阻塞引发的连接池耗尽瘫痪（`GetConnectionTimeoutException`）；
- **开启泄露调用栈审计 (`logAbandoned`)**：
  - 必须配置 `logAbandoned = true`；
  - 发生强制回收时，连接池自动在日志中输出借出连接发生时的调用堆栈，以便开发与运维秒级定位泄漏代码源头。

### 2. 连接健康检查与心跳保活规约 (`testWhileIdle`)
- **空闲心跳探测**：
  - 必须配置 `testWhileIdle = true` 与 `validationQuery = "SELECT 1"`；
  - 空闲连接检测周期 `timeBetweenEvictionRunsMillis` 设为 60000ms（1分钟），最小空闲生存时间 `minEvictableIdleTimeMillis` 设为 300000ms（5分钟）；
  - 彻底消除云环境或网络防火墙切断空闲连接导致的 `Communications link failure` 坏连接通信异常；
  - `testOnBorrow` 与 `testOnReturn` 保持默认 `false`，确保高频借还连接的高性能。

### 3. 慢 SQL 实时审计规约 (`StatFilter`)
- **慢 SQL 阈值与警告输出**：
  - 必须装配 `StatFilter` 慢查询统计监控；
  - 慢查询阈值 `slowSqlMillis` 统一设为 1000ms（超过 1 秒判定为慢 SQL）；
  - 开启 `logSlowSql = true` 与 `mergeSql = true`，自动在日志中以 WARN 级别输出执行超时的 SQL 内容与执行耗时，便于生产瓶颈排查。

### 4. 底层 SQL 注入防火墙规约 (`WallFilter`)
- **SQL 注入防线**：
  - 必须装配 `WallFilter`，设定数据库类型为 `mysql`；
  - **严禁多语句堆叠执行**：配置 `multiStatementAllow = false`，坚决拦截利用分号拼接的多语句攻击（如 `SELECT ...; DROP TABLE ...`）；
  - **拦截危险全表删除与更新**：配置 `deleteWhereNoneCheck = true` 与 `updateWhereNoneCheck = true`，严禁执行无 WHERE 条件的 DELETE 或 UPDATE 语句，彻底杜绝意外或恶意清空整表数据灾难。

## 二十三、 分布式多级缓存（L1/L2）、热 Key 探测与击穿/穿透/雪崩防御规约

### 1. 多级缓存分层架构与透明升降级规约 (`MultiLevelCacheService`)
- **L1/L2 阶梯访问契约**：
  - L1 采用高性能本地缓存 Caffeine（微秒级访问，免网络序列化开销）；
  - L2 采用集中式缓存 Redis（毫秒级分布式共享）；
  - 读取数据时按 `L1 -> L2 -> DB / 数据源加载器` 逐级向下穿透，命中后逐级向上自动回填，实现双层缓存热度平滑传递；
- **Redis 故障透明降级**：
  - `MultiLevelCacheService` 依赖 `StringRedisTemplate` 时必须设计容错回退机制；当 Redis 不可用或未部署时，系统自动优雅降级为 L1 本地缓存模式平稳运行，禁止因外部缓存波动直接导致业务大面积报错。

### 2. 缓存三宗罪（击穿、穿透、雪崩）全方位防御规约
- **热点击穿防御（行级细粒度 Double-Checked Locking）**：
  - 当缓存失效且大量并发线程同时请求同一 Key 时，严禁全并发直接冲击数据库；
  - 必须采用基于 Key 粒度的细粒度互斥锁（如 `ConcurrentHashMap<String, Object>` 行锁池）配合 **双重检查锁（Double-Checked Locking）**；
  - 仅允许第一个竞争到锁的线程执行数据源 Loader，后续线程在获取锁后直接命中一并回填的缓存，最大化保障数据库安全；
- **缓存穿透防御（空值哨兵标记 `@@NULL_SENTINEL@@`）**：
  - 针对查询不存在的数据（Loader 返回 null），系统必须向 L1/L2 写入专用哨兵占位符（`@@NULL_SENTINEL@@`），并设定较短的 TTL（默认 30 秒）；
  - 后续针对该不存在数据的请求直接在缓存层阻断返回 null，杜绝恶意或不存在的 ID 频繁打穿到数据库；
- **缓存雪崩防御（动态随机 Jitter 离散化）**：
  - 严禁对批量缓存设置完全相同的过期时间；
  - 所有写入 L2 Redis 的过期时间必须附加随机抖动时间（`baseTtlSeconds + random(0, jitterSeconds)`，默认 0~15 秒打散），彻底消除周期性全量 Key 同一瞬间过期导致的数据库瞬时雪崩。

### 3. 热点 Key 探测与自动提升规约 (`HotKeyDetector`)
- **滑动时间窗口频次探测**：
  - 针对频繁访问的读多场景，内置基于滑动时间窗口（默认 5 秒）的计数器；
  - 当某个 Key 在窗口内的访问频次达到或超过热度阈值（默认 50 次）时，系统自动将其标记为热点 Key；
- **热点 Key 自动提升 L1 本地缓存**：
  - 探测到热 Key 时，若其尚未在本地缓存，系统自动从 L2 读取并提升沉淀至 L1 Caffeine 中，直接由本地内存抗住海量并发洪峰，显著降低 Redis 网络与 CPU 负载；
- **探测器内存泄漏安全防护**：
  - 滑动窗口记录器必须在检测或定时周期中自动淘汰过期窗口的记录，防止内存无上限膨胀。

### 4. 双层缓存双写一致性与主动失效规约 (`evict`)
- **双层同步清理**：
  - 数据发生新增、修改或删除时，业务代码或消息监听器必须调用 `MultiLevelCacheService#evict(key)`；
  - `evict` 必须原子地同时清理本地 L1 Caffeine 与远端 L2 Redis，彻底避免脏数据长久残留；
  - 分布式场景下推荐结合 Redis Pub/Sub 或 Canal 广播 L1 本地失效事件。

## 二十四、 XXL-Job 分布式任务调度执行器配置、分片广播路由、MDC链路染色与失败告警规约

### 1. 执行器通用自动装配与智能 IP 探测规约 (`XxlJobAutoConfiguration`)
- **执行器配置下沉与条件化装配**：
  - 通用执行器配置必须统一下沉至 `common_core` 底座；通过 `@ConditionalOnClass(XxlJobSpringExecutor.class)` 与 `@ConditionalOnProperty(prefix = "xxl.job", name = "enabled", havingValue = "true")` 条件化装配；
  - 微服务模块只需引入 `common_core` 与配置属性，禁止在各业务模块重复硬编码定义 `XxlJobSpringExecutor` Bean；
- **智能内网 IP 探测**：
  - 若未显式配置 `xxl.job.executor.ip`，底层必须通过 `NetworkInterface` 智能探测本机的非回环、已启用有效的 IPv4 内网地址（`SiteLocalAddress`）；
  - 严禁盲目回退 `127.0.0.1` 导致跨主机或 Docker 容器环境下调度中心无法回调执行器；

  - 执行器 Bean 必须配置 `initMethod = "start"` 与 `destroyMethod = "destroy"`，在 Spring 容器关闭时优雅注销心跳，避免调度中心在节点下线后依然分发流量导致调度失败。

### 2. 全链路 TraceId 自动染色与 MDC 贯通规约 (`XxlJobTraceAspect`)
- **异步调度线程全链路染色**：
  - XXL-Job 任务执行运行在独立的后台工作线程池，必须通过 AOP 切面拦截 `@XxlJob` 标注的方法；
  - 进入任务时自动生成标准化 Job TraceId（如 `job-{jobHandler}-{uuid前8位}`），并注入 `TraceIdContext.setTraceId(...)` 与 SLF4J MDC；
  - 确保定时任务内部打印的日志与下游 Feign 远程调用完整携带 TraceId 链路凭据；
- **执行器线程池防污染清理**：
  - 切面在 `finally` 块中必须强制调用 `TraceIdContext.clear()`；
  - 彻底抹平 ThreadLocal 与 MDC 残留，杜绝执行器工作线程池复用导致的链路串号与内存泄漏。

### 3. 分片广播路由与切片过滤工具规约 (`JobShardHelper`)
- **标准分片信息安全提取**：
  - 获取分片必须通过 `JobShardHelper.getShardInfo()`；
  - 在非调度环境（如本地单元测试、Web 手动触发）或异常情况下，系统必须自动安全回退为单机模式 `(shardIndex = 0, shardTotal = 1)`，严禁抛出任何异常；
- **绝对值哈希取模算法**：
  - 分片判定统一采用 `(Math.abs(id) % shardTotal) == shardIndex`；
  - 针对负数 ID 与 `Long.MIN_VALUE` 必须包含溢出防呆（将 `Long.MIN_VALUE` 防呆转为 `Long.MAX_VALUE`）；
- **内存数据集切片过滤**：
  - 针对大批量数据集，统一使用 `JobShardHelper.filterByShard(list, idExtractor)` 切片，仅由当前节点处理归属于本分片的数据，彻底杜绝集群多实例部署时的重复跑批与并发竞争。

### 4. 任务执行环绕保护、度量与失败告警规约 (`JobAlarmNotifier`)
- **执行结果与耗时度量**：
  - 任务正常执行结束时，切面自动度量执行耗时，并调用 `XxlJobHelper.handleSuccess("执行成功，耗时: ...ms")`；
- **异常捕获与失败摘要**：
  - 任务发生未捕获异常时，切面捕获并提取堆栈前 15 行摘要，自动调用 `XxlJobHelper.handleFail(...)`，并向上抛出以保证调度中心感知；
- **高危失败告警触发**：
  - 任务失败时自动组装 `JobAlarmMessage` 并触发 `JobAlarmNotifier.notifyAlarm(...)`；
  - 默认提供 `LoggingJobAlarmNotifier`，业务微服务可按需扩展实现企业微信、钉钉或邮件 Webhook 实时告警。

## 二十五、 分布式接口防刷与多维度 RateLimiter 限流规约

### 1. 精准滑动时间窗口限流算法规约 (`RedisSlidingWindowRateLimiter`)
- **严禁使用简单固定窗口递增**：
  - 严禁采用简单的 `INCR + EXPIRE` 做长周期限流，避免在窗口切换临界点（如 59s/61s）放行双倍突发洪峰；
  - 必须采用基于 Redis `ZSET` + Lua 脚本的原子滑动时间窗口算法（Sliding Window）；
  - 单次原子执行：清理 `(now - windowMs)` 前的历史过期数据 $\rightarrow$ 统计当前滑动窗口内的总请求数 $\rightarrow$ 判定是否超限 $\rightarrow$ 放行则追加当前时间戳 Member 并刷新 Key 的 TTL。

### 2. 多维度风控隔离与 SpEL 表达式支持规约 (`RateLimitKeyResolver`)
- **多维度隔离契约**：
  - `@RateLimiter` 必须支持以下维度隔离：
    1. `LimitType.IP`：基于客户端真实 IP（结合 `IpUtils.getIpAddr` 穿透多级代理），适用于短信发送、登录注册等防爬虫或防暴力撞库场景；
    2. `LimitType.USER`：基于当前登录用户 ID，适用于数据导出、大屏聚合统计、复杂报表等防重复提交场景（避免高校或企业 NAT 同出口 IP 导致同局域网用户误伤）；
    3. `LimitType.PARAM`：结合 Spring EL 表达式提取特定入参（如 `key = "#phone"`、`key = "#dto.accountId"`），实现业务主键级精细化防刷；
    4. `LimitType.GLOBAL`：接口集群全局总容量保护。
- **未登录安全兜底**：
  - 当指定 `LimitType.USER` 但请求未携带登录态时，系统必须自动优雅降级为 IP 维度进行限制，严禁抛出 NPE 异常。

### 3. 本地高可用容灾与无感知降级规约 (`CaffeineFallbackRateLimiter`)
- **限流组件故障自愈防御**：
  - 限流门面 `RateLimiterManager` 必须具备容错降级机制；
  - 当外部 Redis 集群不可用、连接超时或发生网络分区时，系统必须自动在控制台/日志中记录 WARN，并瞬间无感知切换至本地 Caffeine 滑动窗口限流；
  - 严禁因 Redis 缓存抖动反向导致正常业务大面积报 500 崩溃，确保业务可用性高于限流精准度。

### 4. 标准 HTTP 429 协议与 Retry-After 响应头规约 (`RateLimitException`)
- **抛出结构化异常代替切面强转**：
  - 触发限流时切面必须抛出 `RateLimitException(message, retryAfterSeconds)`，严禁直接在切面中强行 `return Result.error(...)`（防止 Controller 返回类型不匹配引发 `ClassCastException`）；
- **标准协议响应映射**：
  - 全局异常处理器 `GlobalExceptionHandler` 捕获 `RateLimitException` 时，必须映射 HTTP 状态码为 `429 Too Many Requests`；
  - 必须在响应标头中回写 `Retry-After: {seconds}`，便于前端或客户端自动识别并展示倒计时提示或自动置灰提交按钮。

## 二十六、 用户个性化消息通知渠道配置规约

### 1. 业务领域与双渠道独立控制
- **渠道正交性**：
  - 站内信渠道（`internal_enabled`）：控制消息是否写入数据库 `sys_message_info_t` 并在 Web/移动端消息抽屉中展示；
  - 微信通知渠道（`wechat_enabled`）：控制系统是否调用微信服务号模版消息推送接口；
  - 两者完全独立，关闭站内信不会影响微信推送，关闭微信也不会阻碍站内信入库。
- **8 大业务分类字典映射 (`NoticeBizType`)**：
  - `GLOBAL`：全局通知总控（一票否决：关闭后将静音所有业务通知）；
  - `GIFT_EVENT`：礼金大喜事提醒（D-Day/临期倒计时）；
  - `GIFT_RETURN`：人情回礼预警（待还礼与礼金严重失衡提醒）；
  - `COUPON`：消费券到期提醒（到期前3天/前1天/当日到期预警）；
  - `PREPAID_CARD`：猫超卡/预付卡到期提醒；
  - `BUDGET_OVER`：月度预算超支预警；
  - `FINANCE_REPORT`：财务收支智能分析简报推送；
  - `SYSTEM`：基础系统公告与安全提醒。

### 2. 零数据膨胀与两级开关一票否决
- **零数据膨胀原则 (Ponytail 极简原则)**：
  - 严禁在用户注册时批量预插入 8 条冗余配置记录；
  - 默认策略：未配置开关的新用户，数据库无记录，服务层与前端默认全量放行（站内信=开启，微信=开启）；
  - 仅当用户在前端主动切换开关时，才向 `user_notice_config_t` 按需持久化（Upsert 语义）。
- **两级开关与一票否决权**：
  - `GLOBAL` 总开关具有最高决定权：
    若用户的 `GLOBAL.internal_enabled = false`，所有业务子项的站内信均被一票否决；
    若用户的 `GLOBAL.wechat_enabled = false`，所有业务子项的微信推送均被一票否决；
    仅当 `GLOBAL` 为开启时，才由具体业务子项的开关进行独立判定。

### 3. 用户上下文与越权防护
- **防越权规约**：
  - 获取与保存配置必须从当前安全会话（`UserUtils.getLoginUser()`）提取 `userId`，严禁信任前端传入的 `userId` 字段；
  - 实体主键 `id` 与外键必须在 VO 中统一使用 `@JsonSerialize(using = Long2StringSerializer.class)` 序列化为前端 String。
