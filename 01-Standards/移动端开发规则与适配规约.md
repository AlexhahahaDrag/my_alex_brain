## 1. 技术栈与移动端适配基准

- **核心框架**：Vue 3 + TypeScript + Vite；
- **包管理工具**：`pnpm`（CAS 全局硬链接存储，与 PC 端共享依赖池）；
- **组件库**：Vant 4 (`vant`)；
- **标准基准视口**：`390 × 844` (iPhone 12/13/14 标准尺寸)；
- **全面屏安全区**：遵循 iOS / Android Safe Area 规约，底部留足 `padding-bottom: env(safe-area-inset-bottom)`；
- **自动化插件**：`unplugin-auto-import` 与 `unplugin-vue-components`（常用 API 如 `ref`, `computed`, `watch`、`src/composables` 下所有业务 hooks 及 Vant 组件自动解析导入，**严禁在页面中重复手动显式 import**）。

## 2. 移动端强制工程红线与范式 (Ponytail Red Lines)

> [!CAUTION]
> ### ⛔ 严禁违背的三大移动端红线
> 1. **日期/时间统一收敛于 `@/utils/dayjs`（仅导出类型，禁导实例）**：
>    - 严禁在业务页面或组件中直接 `import dayjs from 'dayjs'`，底座 `src/utils/dayjs/index.ts` 仅导出 `type Dayjs`，不导出 `dayjs` 实例；
>    - 统一引入并使用 `@/utils/dayjs` 中封装好的工具函数：
>      - `formatDate(val?, format?)`：格式化日期（默认 `YYYY-MM-DD`）；
>      - `formatTime(val?, format?)`：格式化时间（默认 `YYYY-MM-DD HH:mm:ss`）；
>      - `formatMonth(val?)`：格式化月份（`YYYY-MM`）；
>      - `formatDayjs(val?)`：安全构造 Dayjs 实例（为空默认当前时间）；
>      - `nowDayjs()`：获取当前时间 Dayjs 实例；
>      - `getMonthRange(dateOrOffset?)`：获取 `[月初, 月末]` 字符串元组，严禁手写散乱的 `dayjs().startOf('month').format(...)` / `dayjs().endOf('month').format(...)`；
>      - `getMonthRangeDayjs(dateOrOffset?)`：获取 `[Dayjs, Dayjs]` 元组供选择器范围绑定；
>    - 严禁各个组件私自 `npm install` 其他散乱的时间解析库。
> 2. **响应式导航栏配置范式**：
>    - 移动端导航栏配置，统一使用响应式配置模式：
>      ```typescript
>      const info = ref<Pick<NavBarConfig, 'title' | 'rightButton' | 'leftPath'>>({
>        title: '页面标题',
>        rightButton: true,
>        leftPath: '/home'
>      });
>      ```
> 3. **轻量触觉反馈原生实现**：
>    - 关键交互（如记账键盘点击、快速还礼反填、核销确认）优先使用轻量封装的原生 `navigator.vibrate`，严禁引入臃肿的外部手势动效库。
> 4. **Pinia 持久化白名单与内存状态隔离**：
>    - 移动端 `useUserStore` 必须配置 `paths` 白名单，严禁将路由标志位 `hasMenu`、`sessionTimeout` 或时间戳等无差别写入 `localStorage`，防止关闭页面或刷新时受旧版本脏缓存干扰；
> 5. **动态路由生命周期与双保险**：
>    - 全局路由守卫必须维持 `if (!userStore.getRouteStatus || routes.length <= BASE_ROUTE_COUNT)` 物理双保险；
>    - 动态路由加载函数 `addRouter()` 在注册遍历前必须先执行 `routes.splice(BASE_ROUTE_COUNT)` 做重入防护裁剪，避免多次导航累积重复路由项；所有动态视图组件统一走 `markRaw()` 包装，杜绝深层代理。
> 6. **通用组件收敛与 Views 纯粹性 (Ponytail 极简规约)**：
>    - **组件归拢**：全局通用 UI 与图表组件必须统一收拢于 `@/components/`，严禁散落于 `views/common` 或 `views/components`；
>    - **Views 目录纯粹性**：`src/views/` 严格专属于真实业务页面视图，严禁在此建立只有 `api/` 和 `config/` 的幽灵目录；通用文件上传 API 统一对齐 PC 端收敛至 `@/views/common/api/file.ts`；
>    - **YAGNI 极简原则**：严禁过度面向对象包装（如无用接口、类代理、单例工厂），工具库以高内聚纯函数为主。
> 7. **SonarQube S2589 规约与 TypeScript 类型收窄规范**：
>    - 在已被 `if (id)` 判定为 Truthy 的条件分支内部，严禁再次编写 `id || '-1'` 或 `id || ""` 等死代码回退逻辑；
>    - 彻底杜绝 SonarQube `typescript:S2589`（*This always evaluates to truthy*）告警，保持代码精简与类型推断纯洁性。
> 8. **静态资源与 SVG 引用范式 (`assets/icons` vs `assets/images`)**：
>    - **SVG Sprite 符号图标 (`assets/icons`)**：专属于 `vite-plugin-svg-icons-ng` 自动注册为 `<svg><use xlink:href="#icon-name" /></svg>` 的单色/多色矢量图标，配合 `SvgIcon.vue` 组件渲染；
>    - **图片与插画静态资源 (`assets/images`)**：凡需通过 `<van-image :src="imgUrl" />` 或 `<img>` 直接渲染的静态 SVG 图标或插图，统一归入 `@/assets/images/` 并通过静态 `import img from '@/assets/images/...'` 注入真实 URL，严禁混入 `assets/icons` 导致 Symbol 冲突或图像空白。
> 9. **路径别名强制使用规范 (Path Alias Standard)**：
>    - 所有模块、配置文件、API 接口、数据类型及组件的导入，**一律强制统一使用 `@/` 路径别名**（例如 `@/views/finance/gift/config`、`@/views/finance/financeManager/api`）；
>    - **严禁使用任何相对路径（如 `./`、`../`、`../../`）**，杜绝层级相对寻址带来的歧义与移动文件时的断链隐患，与 PC 端工程规约保持高度一致。
> 10. **页面初始化与生命周期规约 (Page Init Lifecycle & Defensive Pattern)**：
>     - **禁止顶层裸调**：严禁在 `<script setup>` 顶层直接裸调 `init()`、`void init()`、`refresh()` 或异步加载函数，所有页面初次数据装配一律统一收敛至 `onMounted` 钩子中（`onMounted(() => { void init(); })`），消除 DOM 挂载前并发与 KeepAlive / 路由守卫拦截时的时序竞态；
>     - **完备异常防御与友好提示**：页面数据加载函数（如 `init()`）必须具备 `try...catch` 兜底保护，出现网络异常或业务错误时通过 `showFailToast` 给出明确提示并在 `finally` 中可靠释放 `loading` 状态；编辑模式（带 `id` 传参）下若详情查询失败，严禁静默回退至“新增默认值”，杜绝用户误操作；
>     - **自动导入约束**：由于项目已通过 `unplugin-auto-import` 全局注入生命周期钩子，**严禁在页面中手动显式 `import { onMounted } from 'vue'`**。
> 11. **详情/表单页面公共请求解耦与消除魔数下标规约 (Init Request Decoupling & Anti-Magic-Index SOP)**：
>     - **公共数据与按需详情绝对解耦**：所有表单详情页面（无论是新增还是编辑状态），公共依赖的字典列表、选项枚举必须统一在最外层公共区域先行加载并初始化（如 `const [dictRes] = await Promise.all([getDictList(...), ...])`），仅执行一次；
>     - **严禁双重 `tasks` 混排**：严禁将公共任务放入数组，再在 `if (id)` 中将详情拼接在首位而在 `else` 中单独运行；这会导致 `res[0]` vs `res[1]` 产生脆弱的魔数索引位移，且引发在两处分支重复调用字典解析函数的代码异味；
>     - **详情专线拉取**：编辑态仅专线 `await getDetail(id)` 并回填表单与关联选项展示名称，逻辑线性清晰，易测易维护。

## 3. 移动端 AI 自动化测试体系 (Midscene + Playwright Probe)

- **技术组合**：`@midscene/web` + `@playwright/test`；
- **视口与环境模拟 (Mobile Emulation)**：默认必须配置 `viewport: { width: 390, height: 844 }` + `isMobile: true` + `hasTouch: true`，真实模拟 iPhone 12/13/14 标准尺寸与触屏手势；
- **触觉副作用断言 (Haptic Probe)**：
  - 在页面导航前通过 `page.addInitScript(installHapticProbe)` 注入探针，拦截原生 `navigator.vibrate` 调用；
  - 探针将振动时长记录至 `window.__hapticCallCount` 与调用栈数组中，在测试中通过 `page.evaluate(() => window.__hapticCallCount)` 精确断言触觉反馈触发次数，确保触觉无障碍与操作反馈真实生效；
- **可交互 DOM 规约**：所有可交互元素与抽屉按钮必须挂载标准 `data-testid`（如 `gift-record-open-add-button`, `gift-record-ai-input`, `gift-record-ai-parse-button`, `gift-record-ai-recommend-card`, `gift-record-copy-greeting`），严禁使用易碎的中文文案做精确匹配；
- **等待策略**：严禁使用 `Thread.sleep` 或 `waitForTimeout`，统一采用 `waitForResponse` / `waitForSelector` / `locator.waitFor({ state: 'visible' })` / `aiWaitFor`；
- **微服务接口 Mock 与加解密契约护城河**：
  - **严格路由拦截前缀**：在独立 E2E 脚本（如 `run-mobile-ai-smoke.mjs`）中进行路由 Mock 时，**必须且仅拦截以 `/api/am-` 开头的微服务后端接口**（即 `url.pathname.startsWith('/api/am-')`），严禁匹配宽泛的 `**/api/**`，防止误拦截 Vite 动态加载的前端模块源码（如 `src/views/.../api/index.ts`）导致 504 / MIME 模块解析失败；
  - **网关 AES-128-CBC 统一加密**：移动端 Axios `responseHandler` 挂载全局对称解密逻辑。Mock 响应体数据**必须统一经过 AES-128-CBC 加密**（密钥 `20230610HelloDog`，偏移量 `1234567890123456`）转为 Base64 密文，防止前端反序列化崩溃；
  - **级联选项数据契约完整性**：AI 自然语言快速解析（`handleAiParse`）后会立即调用 `loadPickerOptions()`，发起 `/gift-person-info-t/list` 与 `/gift-event-info-t/list` 请求。Mock 必须返回预置对象的 JSON 数组（含 `id`, `personName`/`eventName`），避免前端调用 `.filter()` 时报空指针或类型错误；且 AI 解析响应必须包含有效 `personId` 与 `eventId` 以正常触发推荐卡片与贺词区域渲染；
- **跨平台多浏览器通道弹性启动 (Browser Launch Resilience)**：
  - Playwright 启动时配置自动降级链路：优先启动独立 Chromium 实例，若未安装 standalone shell 则自动回退至系统内置通道 `channel: 'msedge'` 或 `channel: 'chrome'`，保证在本地开发与 CI 环境均能秒级启动；
- **运行命令**：
  - 移动端 AI 快速记账与贺词烟测：`pnpm test:ai:smoke`（执行 `node scripts/playwright/run-mobile-ai-smoke.mjs`）；
  - 移动端礼金全量自动化测试：`pnpm test:midscene:gift:local`。

## 4. 移动端主题换肤与深色模式适配规约 (Theme & Dark Mode)

- **设计理念**：遵循 Ponytail 极简模式，0 引入第三方取色或换肤包。全面基于 Vant 4 官方原生 `<van-config-provider>` 引擎与 HTML5 原生 `<input type="color">` 拾色器实现。
- **状态存储**：由 `useThemeStore` (`@/store/modules/theme.ts`) 统一响应式维护 `primaryColor` 与 `isDark`，通过 `pinia-plugin-persistedstate` 保存在 `localStorage('app-mobile-theme')`。
- **根级 Token 注入**：`App.vue` 顶层使用 `<van-config-provider :theme="themeStore.isDark ? 'dark' : 'light'" :theme-vars="themeVars">` 包裹 `<router-view>`，并在 `onMounted` 触发 `themeStore.initTheme()` 同步冷启动 DOM。
- **全局变量与深色桥接**：在 `variables.css` 中为 `html.dark, html.van-theme-dark` 声明深色模式语义变量（`--bg-color: #121212; --card-bg: #1e1e1e;`），并将 `--van-primary-color` 绑定至 `--primary-color`，使非 Vant 自定义容器与 Vant 原生暗黑模式无缝融为一体。
- **移动端交互范式**：主题切换以底部抽屉（`<van-popup round position="bottom">`）承载，支持明暗 Switch、预设经典色块点选与系统原生色盘吸色，所有点选动作必须配合 `navigator.vibrate(40)` 轻微触觉反馈。

## 5. 移动端 AI 快速记账与智能推荐交互范式 (AI Fast-Entry & Haptic Feedback)

- **AI 自然语言快速记账面板 (`.quick-ai-parse-box`)**：
  - 快速记礼抽屉顶部提供多行自然语言录入域与「智能解析」药丸按钮，输入单句文本一键解析流向、金额、亲友、事由与备注并自动回填；
  - 严格保持 ID 安全契约，通过 `normalizeGiftAiParseVo` 保证解析返回的实体 ID 为 `string` 类型；
  - 抽屉初始化/关闭重置时需同步清空 AI 输入框状态；
- **AI 推荐考量与场景贺词助手 (`.ai-recommend-card`)**：
  - 联动展示 `💡 礼金考量`（人情世故与建议说明）与 `🎉 场景贺词`；
  - 提供「复制」按钮，点击自动将贺词文本复制至剪贴板并轻提示；
- **全链路触觉震动反馈 (Haptic Feedback)**：
  - 解析完成、贺词复制、表单提交等节点均触发 `haptic()`（`navigator.vibrate(50)`）原生触感反馈，打造细腻丝滑的手感。

## 6. 移动端首页信息架构与分组卡片流规范 (Home Architecture & Grouped Cards)

- **目录层级物理级解耦**：
  - 严禁将一级导航分类与二级叶子功能并列打平混入九宫格网格；
  - 一级目录（如【用户权限】、【财务信息】、【猫超管理】）作为**独立分组卡片（`MenuGroup`）**及其 Header 呈现，并展示分类色标与项数徽标；
  - 只有具备真实访问页面的二级叶子节点才作为卡片内部的功能按钮，彻底杜绝点击纯目录导致的白屏或跳转异常；
- **4列紧凑网格系统 (`repeat(4, 1fr)`)**：
  - 采用 4 列网格排布，图标包裹容器固定 `44 × 44px` 微圆角拟物底色，图标 `22 × 22px`，文字字号 `12px`，最大支持双行文本截断；
- **全局功能实时搜索过滤**：
  - 顶部集成 `<van-search>`，支持按功能名称、模块名称模糊匹配，实时过滤高亮卡片项，无结果呈现友好的 `<van-empty>`；
- **多状态自适应与触感反馈**：
  - 无保存记录时展示基于 `@/utils/dayjs` 格式化的今日日期与欢迎横幅；
  - 点击任何功能项必须配合 `navigator.vibrate(40)` 触觉反馈与缩放微动效。

## 7. 移动端列表默认过滤与搜索交互规约 (List Initial State & Global Search)

- **初始态免约束直出（Zero-Constraint Baseline）**：
  移动端流水、记账、账单等列表页面首次挂载加载时，时间预设默认值必须设为**「全部（`all`）」**而非当月或当日；通过服务端物理分页（如 `pageSize: 10`）进行自然加载，严禁因预设狭窄时间窗口导致月初或低频用户一进页面就遭遇假空屏（「没有找到符合条件的账单」）。
- **全局搜索覆盖全生命周期**：
  顶部关键字搜索框（`<van-search>`）检索时，必须能够匹配历史全量数据。列表初始无时间限制可避免将关键字局限在窄区间内导致搜空；重置筛选（`onResetFilters`）时也必须严格同步将时间重置为 `all`，保持状态心智 100% 一致。

## 8. 移动端细粒度权限校验与属主数据保护规约 (RBAC & Owner-Scoped Protection)

- **多权限码数组支持 (OR 语义)**：
  `hasPermission(code?: string | string[])` 与底座 `canAccessPermission(set, code, isSuperAdmin)` 原生支持字符串或字符串数组入参。传入数组时采用 OR 语义判定（如只要具备 `budget:view` 或 `budget:edit` 任意一项即可展示入口）。
- **数据属主保护规范 (Owner-Scoped Protection)**：
  对家庭成员等普通成员角色，即使持有功能模块级 `edit` 或 `delete` 权限，也必须在 UI 与交互层严格进行**个人属主校验**：
  ```typescript
  const canDelete = computed(() => {
    if (!hasPermission('finance:financeManager:delete')) return false;
    if (isSuperAdmin.value || isFamilyAdmin.value) return true;
    return String(item.belongTo || '') === String(userStore.getUserId);
  });
  ```
  - 卡片侧滑删除按钮：仅在具备权限且属于个人记录（或为管理员）时展示；
  - 详情修改页面：查看他人记录时自动呈现只读提示条，保存按钮置灰或隐藏，严防相互篡改。
- **二级独立动态路由解耦规范**：
  复杂功能（如零花钱预算配置、大盘试算）若包含输入交互、分类池选择与实时模拟，严禁长期堆叠在超过 150 行的内嵌弹窗组件中。统一通过后端 `t_menu_info` 配置 `hide_in_menu: '1'` 的二级独立动态路由，前端在 `src/views/...` 建立标准全屏页面承载，挂载独立权限码（如 `finance:financeManager:budget:view`），并在主列表页通过 `onActivated` 实现返回即时数据刷新。

## 9. 移动端公共图表组件规约 (ECharts Common Components)

- **公共图表目录收敛**：
  所有通用图表组件必须统一维护在 **`src/views/components/chart/`**，严禁在 `src/views/model/` 或各个业务页面内私自堆砌：
  - `BaseChart.vue`：核心基座，基于 Vue 3 原生 `shallowRef<HTMLDivElement>()` 进行图表挂载，强类型化 `echarts.ECharts`，自带原生 `resize` 监听防泄漏与销毁回收，**严禁引入 `nanoid` 或通过 `document.getElementById` 查询 DOM**；
  - `PieChart.vue`：开箱即用环形/饼图组件，接收标准 `[{ name, value }]` 数据数组，内置语义调色板与优雅 tooltip；
  - `BarChart.vue`：多系列柱状/折线复合图组件，支持多轴与堆叠计算；
  - `types.ts`：图表统一契约定义（如 `BarItem`, `PieChartItem` 等）。
- **组件自动导入生态**：

## 10. 移动端大页面组件拆解与瘦身工程范式 (View Decoupling & Slimming)

- **单文件规模红线与解耦基线**：
  核心业务页面单文件必须严格控制规模，**严禁产生超过 800 行的巨石单文件 (Monolithic View)**；推荐主页面代码控制在 200~450 行以内，保持高可读性与低认知负荷。移动端全量视图实现 800+ 行单文件清零。
- **解耦拆分黄金原则**：
  1. **纯逻辑抽离 Composable**：
     - 凡涉及繁重的时间芯片计算、日期范围过滤、Query 参数组装、标签清除与日历联动等逻辑，统一抽离为同级 `composables/useXxxFilter.ts`（如 `useCouponFilter.ts`、`useFinanceFilter.ts`），保持主页面关注点集中在视图与生命周期调度；
  2. **高内聚 UI 卡片独立化**：
     - 随主列表滚动的重度卡片（如本月零花钱折叠条 `PocketMoneyCard`、预付卡轮播 `PrepaidCardSwipe`、单条流水卡片 `PrepaidTransactionList`、消费券滑动单元格 `CouponCardItem`、AI 试算模拟卡片 `BudgetSimulationCard`）必须独立封装在 `components/` 下，自包含动画展开/折叠状态、微环境进度条与私有样式；
  3. **交互控件与底部弹窗独立封装**：
     - 包含特定防呆、格式化、防溢出与触觉震动的复杂控件（如 4×4 底部记账虚拟数字键盘 `FinanceKeypad`、九宫格分类网格 `FinanceCategoryGrid`）以及重度底部操作弹窗（如集成 Web Speech 语音录入、AI 智能记礼解析、场景贺词助手的 `GiftQuickRecordPopup`）必须独立封装为子组件，通过 `v-model:show` 及轻量 `@success` 回调与主列表交互，且务必完整保留 `data-testid` 契约；
  4. **双模页面视图与表单分离 (Profile vs Form)**：
     - 当页面同时承担「画像展示查看」与「编辑/新增表单」双重职责时（如 `giftPersonDetail`），必须将画像展示（Profile View）与表单（Edit Form）彻底解耦为两个独立子组件，主页面仅作为轻量路由控制器与权限调度器；
  5. **常量字典剥离 types.ts 与 config/index.ts**：
     - 预设分类数组、静态图标映射、金额格式化与状态拆分助手（如 `getBalanceParts`、`getStatusLabel`）必须收敛在同级 `config/index.ts` 或 `types.ts` 中，严禁在 `<script setup>` 中散落纯逻辑工具函数。

## 11. 移动端垂直领域契约锁与单元测试标准 (Mobile Contract Lock & Unit Testing Standard)

## 12. 触觉微交互分级与离线快照秒开范式 (Haptic Feedback & Offline Cache)

- **触觉微交互中枢规范 (`@/utils/haptics`)**：
  - 严禁业务页面随意散落硬编码 `navigator.vibrate?.(...)`，统一通过 `triggerHaptic(type)` 触发规范分级振动：
    1. `selection` (10ms)：数字键盘输入、单选切换；
    2. `light` (15ms)：分类点选、标签切换、轻量触碰；
    3. `medium` (30ms)：弹窗抽屉展开、浮层调出、卡片折叠；
    4. `heavy` (50ms)：长按手势、删除确认；
    5. `success` (`[15, 60, 25]`ms)：记账成功、保存完成双重微振；
    6. `warning` (`[30, 80, 30]`ms)：表单未填提示、超支预警；
    7. `error` (`[50, 100, 50, 100, 50]`ms)：网络断开或请求异常；
  - 工具层自动捕获异常并在不支持震动的设备或静音环境下平滑静默降级；
- **高频分类自适应记忆排序 (`useCategoryFrequency`)**：
  - 记账分类网格（`FinanceCategoryGrid`）根据本地使用频次（`localStorage`）动态自适应加权排序，高频使用的分类（如餐饮、交通）自动置顶于首排，显著降低翻找成本；
- **大盘离线图表与 SWR 秒开范式 (`useAnalysisOfflineCache`)**：
  - 资产总览（总额、同比环比、动产/不动产）、收支分类占比饼图（`incomeAnalysis`）与日/月消费走势图（`incomeDetail`）全面纳入 SWR 离线快照；
  - 页面加载时优先反序列化已有快照绘制图表骨架，最新数据返回后利用 ECharts 内置补间动画平滑过渡换新，消灭切换 Tab 与月份时的白屏感；
- **移动端图表容器重绘韧性 (`BaseChart`)**：
  - 严禁单纯依赖 `window.onresize` 监听移动端图表，必须通过原生 `ResizeObserver` 动态监听图表外层 DOM 容器；
  - 结合 100ms 防抖调度 `chartInstance.resize()`，彻底杜绝由于 `<van-tab>` 滑动切换、组件懒加载或抽屉展开导致的图表宽度塌陷或自适应迟滞。

## 13. 移动端 AI 记账悬浮球与流式多阶段打字机抽屉交互范式 (Mobile Copilot & Streaming Standard)

- **轻量吸附悬浮球 (MobileAiFloatingBubble)**：
  - 固定定位在右下角（z-index: 990，默认避开底部 TabBar 与安全区），内嵌晶体图标与呼吸光晕环动效（pulseGlow）；
  - **垂直拖拽与贴边吸附**：通过 	ouchstart/	ouchmove/	ouchend 监听手势，垂直位置严格被限制在安全区域内（[60, screenHeight - 120]px）；
  - **防误触阈值**：位移超过 5px 标定为拖拽操作，抑制点击事件；点击时触发 	riggerHaptic('light') 并唤起 AI 记账抽屉；
- **流式多阶段打字机抽屉 (FinanceAiSheet)**：
  - **SSE 逐字打字机与思考链**：展示大模型流水语境推理日志，配合 .typing-cursor 呼吸闪烁光标；支持展开/收起切换；
  - **多阶段进度演进**：联动 SCENE_ANALYSIS (10%) -> FIELD_EXTRACTION (70%) -> CATEGORY_MATCHING (90%) -> COMPLETE (100%)，阶段跃迁触发 	riggerHaptic('light')，完成触发 	riggerHaptic('success')；
  - **雪花 ID 精度安全防御**：解析回传的储值卡 ID (prepaidCardId) 与归属人 ID (elongTo) 统一强制转换为 string，彻底杜绝前端 JS 64 位大数低位截断；
  - **无感平滑保底**：当 SSE 流式连接或长连接中断时，静默切换至同步 parseUniversalFinanceLedger 接口，杜绝白屏或卡死。
